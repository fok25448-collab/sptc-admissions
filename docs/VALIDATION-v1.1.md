# การตรวจสอบ v1.1.0

ผลรันล่าสุด: Build / Syntax ผ่าน, Unit–API–PostgreSQL **12/12 ผ่าน**, Chromium browser flows **9/9 ผ่าน**

## ขอบเขตที่ตรวจ

- Build หน้าเว็บครบ 6 หน้า: หน้าแรก หลักสูตร สมัคร ติดต่อ ตรวจสถานะ และเจ้าหน้าที่ ใช้เมนูและท้ายหน้าร่วม
- ตรวจ JavaScript syntax ของ API, server, frontend และ scripts
- Unit / API / PostgreSQL tests 12 รายการ: ข้อมูลใบสมัคร, วุฒิ, GPA, วันเกิด, ความพิการ, ID/โทรศัพท์, ลายเซ็นคำขอ, ไฟล์ทั้ง 4 รายการ, การส่งซ้ำ, สถานะที่ไม่เปิดเผยข้อมูลส่วนตัว, สิทธิ์ admin, cookie, migration, จำนวนรับ, การอนุมัติที่ต้องตรวจเอกสารครบ, การบันทึกพร้อมกัน และการล้างไฟล์แบบเก่า/ใหม่
- Browser flows: ขนาด 390 / 820 / 1440 px, เมนูมือถือ, ไม่มีแนวนอนล้น, เลือกหลักสูตรข้ามหน้า, แบบร่าง, สมัครออนไลน์และยื่นด้วยตนเอง, retry, ดาวน์โหลด PDF จริง, ตรวจสถานะ, ตรวจเอกสารจริงและอนุมัติ, แบบฟอร์มติดต่อ
- PDF: ตัวอย่างข้อมูลสมมติของ ปวช. และ ปวส. เป็น A4 หน้าเดียว ตรวจภาษาไทย การขึ้นบรรทัด พื้นที่ลายเซ็น และบัตรผู้สมัครท้ายใบ การทดสอบผ่านเบราว์เซอร์ใช้รูปสมมติและดาวน์โหลดไฟล์จริง

## ลักษณะการทดสอบ

ฐานข้อมูลใช้ PostgreSQL ผ่าน PGlite และจำลองตาราง storage.buckets เฉพาะที่ต้องใช้ตอนติดตั้ง การทดสอบ HTTP และเบราว์เซอร์ใช้ fixture ไม่ใช่ข้อมูลผู้สมัครจริงและไม่ใช่การเชื่อมบัญชี Supabase จริง

รูปภาพใน PDF ถูกถอดรหัสและแปลงเป็น JPEG พื้นขาวก่อนฝัง เพื่อลดความต่างของการแสดง PNG โปร่งใสในโปรแกรมอ่าน PDF ไม่เปลี่ยนไฟล์ต้นฉบับที่เก็บเป็นหลักฐาน

## ก่อนเปิดใช้จริง

1. รัน migration 003 หลังโครงสร้างรุ่นก่อน และตรวจ private Storage bucket
2. ตั้ง Environment Variables ของ Vercel และ APP_ORIGIN ให้ตรงโดเมนจริง
3. สร้าง Supabase Auth user ของเจ้าหน้าที่และเพิ่มสิทธิ์ใน admin_users
4. ตรวจหลักสูตร เกรดขั้นต่ำ จำนวนรับ ปีการศึกษา และกำหนดการกับงานทะเบียน
5. ทดลองอัปโหลดจริง ดาวน์โหลด PDF ล็อกอินเจ้าหน้าที่ อนุมัติ และค้นสถานะจากอีกอุปกรณ์ด้วยข้อมูลทดสอบ
6. ตรวจไฟล์รูปเดิม ลิงก์ติดต่อ และข้อมูลประชาสัมพันธ์ก่อนเผยแพร่

ยังไม่ได้สร้าง GitHub repository หรือ Deploy เข้าบัญชี Vercel / Supabase ของเจ้าของระบบจากสภาพแวดล้อมนี้
